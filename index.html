One conversation.
One provider.
The split still holds.

Bifrost can split AI traffic across providers, say 70% Claude and 30% GPT. Today it rolls that split on every message, so one conversation keeps jumping between providers. StickyRoute adds one opt-in setting that keeps each conversation on one provider, while conversations still split 70/30.

The problem: the waiter changes with every dish

Imagine a restaurant where the owner says “Waiter A serves 70% of tables, Waiter B 30%.” Sensible. Now imagine the waiter changes with every dish at the same table. That is what weighted routing does to AI conversations today.

Conversations break

Providers format messages and tool calls differently. Switching mid-thread causes errors and lost context.

The prompt cache is thrown away

Providers cache the conversation so repeat turns are cheaper. Caches are per provider, so every switch pays full price again.

The model changes mid-thread

Style and capability jump between turns, and users notice.

It also undoes a feature Bifrost already has: session affinity keeps a conversation on its last provider only while routing still offers that provider, and every random re-roll to the other target drops it.

How it works

  1. Turn it on per rule

    One field on a routing rule, off by default: "sticky_sessions": true. From the dashboard, the API or config.json.

  2. Reuse the session ID Bifrost already reads

    x-bf-session-id, or the headers Claude Code, Codex and OpenCode send. No new header.

  3. Score every target, pick the highest

    Weighted rendezvous hashing: score = weight / −ln(hash(session, rule, target)).

  4. Let Bifrost handle failover

    If the chosen provider fails, Bifrost’s session affinity binds the conversation to the fallback that answered. A stable pick is what lets that binding survive.

Same session, same target

Every message of a conversation lands on the same provider.

The split stays exact

70.08% of 100,000 sessions picked the 70% target.

Changes move only what must move

Remove a target and only its own conversations move. Target order never matters.
